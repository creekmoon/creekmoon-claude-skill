# 组件规则

组件级的具体做法。所有组件共享的底线：交互状态完整（hover / focus / active / disabled / loading）、尺寸稳定（内容变化不引起跳动）、语义一致（同一动作全站同一形态）。

## 按钮

- 四级层级：主按钮（实心主色）、次按钮（边框或浅底）、文本按钮（无底无边）、危险按钮（实心 danger）。**每屏一个主按钮**，其余动作降级。
- 高度档位：32px（紧凑表格内）/ 36px（后台默认）/ 40-44px（表单提交、营销页）。同一行内的按钮和输入框必须同高。
- 内边距：左右 = 高度的 40-50%（36px 高配 14-16px 左右内边距）；图标与文字间距 6-8px。
- **按下必须有物理反馈**：`:active` 时 `transform: scale(0.97)`（幅度取 0.95-0.98），配 100-160ms 过渡。这是"界面听见了"的即时确认，缺了它按钮就像贴在页面上的图片。所有可按压元素同理——卡片按钮、图标按钮、列表项。
- 禁用态用降透明度（0.5）+ `cursor: not-allowed`，不要把按钮藏起来——用户需要知道这个能力存在，只是现在不可用。
- 加载态：按钮内文字换成 spinner + 原文案（或固定"提交中…"），**宽度保持不变**（`min-width` 或占位），否则布局跳动。
- 纯图标按钮必须有 tooltip 和 `aria-label`。
- 危险操作（删除、清空）需要二次确认或可撤销，且确认按钮文案写明动作（"删除 3 项"而不是"确定"）。

## 表单

- **label 永远可见**，放输入框上方（4-8px 间距）。placeholder 只写示例格式（"如 138xxxx0000"），不承载说明——输入后说明就消失了。
- 输入框高度与按钮档位一致；聚焦态用 2px 主色 focus ring（`box-shadow: 0 0 0 3px rgba(主色, 0.15)` + 边框变主色），不要只靠浏览器默认 outline，但也绝不移除 outline 而不给替代。
- 校验错误：内联显示在字段正下方（danger 色 12-13px + 边框变红），提交失败时在表单顶部汇总并滚动到第一个错误字段。错误文案写"怎么改"而不是"不合法"。
- 相关字段分组（标题 + 间距），组内间距 16-20px、组间 32-40px。单列布局；只有强关联的短字段（省/市、起/止日期）才共行。
- 必填标记全站统一（推荐只标"选填"，因为多数字段必填时标必填是噪音）。
- 优先用原生 `select`、`input[type=date]` 等控件，自定义控件只在产品确有需要时做，且必须保住键盘导航和屏幕阅读器语义。

## 表格

- 数字列右对齐 + `tabular-nums`；文本列左对齐；不要居中对齐数据列。
- 表头 12-13px、secondary 色、可加 500 字重；不需要背景色块也能成立。
- 行分隔用 1px `--border` 细线；斑马纹只在超宽表格（列多到难以追行）才用。行 hover 高亮（背景加 2-3% 灰度）。
- 行高档位：紧凑 36px / 默认 40-44px / 宽松 48px+，按数据密度选。
- 状态列用徽章或色点 + 文字，不要只用颜色（色盲不可读）。
- 操作列固定在最右；行内操作超过 3 个收进 `···` 菜单；批量操作条在选中行后出现（顶部浮出，显示"已选 n 项"）。
- 单元格文本溢出用省略号 + tooltip，不换行撑高行。
- 长表格表头吸顶；数字列宽度按最长值预留，避免翻页时列宽跳动。

## 卡片与分组

- 卡片只在"这个块是独立交互单元"（可点击进入、可独立操作、在网格中并列比较）时使用。纯粹的信息分组用间距 + 分隔线 + 小标题表达。
- 禁止卡片套卡片。需要嵌套层次时，内层用更浅的背景色阶或分隔线。
- 同页所有卡片用同一种表面处理（同圆角、同边框/阴影策略），即使内部布局不同。
- 卡片 padding：紧凑 16px / 默认 20-24px；标题与内容间距 8-12px。

## 徽章与状态

- 形态：低饱和浅底 + 深色同系文字（如 `--success-bg` + `--success`），4-6px 圆角或胶囊形，12px 字号，2px/8px 内边距。
- 全站同一状态同一颜色同一文案；"已完成/成功/完成"这类同义词要统一成一个。
- 徽章是名词或状态（"运行中"），按钮才是动词；不要把徽章做成可点击的样子。

## 导航

- 当前位置必须明确：激活项用背景色块或左侧指示条 + 文字变 primary 色，不能只靠字重差异。
- 侧栏导航项高 36-40px，图标 16-20px 与文字 8-12px 间距；分组用小标题（12px、muted、可加字距）。
- 导航在视觉上比内容区安静：inactive 项用 secondary 色，hover 才提亮。
- 面包屑用于层级 ≥3 的后台；tab 用于同一对象的平级视图，tab 切换不应丢失已输入状态。

## 状态设计（loading / empty / error）

- **加载**：列表和卡片用骨架屏（灰块按真实布局占位），局部小区域用 spinner；骨架屏结构要贴近真实内容，不要一个大灰块。已有数据刷新时不清空旧数据，用半透明或角落 spinner 表示"更新中"。
- **空状态**：说明为什么是空的（"还没有创建任何项目" vs 筛选无结果的"没有匹配项"是两种空），并给下一步动作（创建按钮 / 清空筛选）。图形装饰可有可无，动作必须有。
- **错误**：写清楚发生了什么 + 用户能做什么（重试按钮、联系方式、回退路径）。表格加载失败不要显示空状态——"没有数据"和"取不到数据"是完全不同的信息。
- **部分成功**：批量操作要报告"成功 8 项，失败 2 项"并列出失败原因，不要只弹一个"操作完成"。

## 图标

- 全站一套图标库（Lucide / Heroicons / Phosphor / Tabler 任选其一），统一描边粗细和尺寸（16px 行内 / 20px 按钮与导航 / 24px 独立）。
- 图标必须传递信息（动作、类型、状态）才存在。装饰性图标——尤其"每个卡片标题配一个圆底图标"——直接删掉。
- 行内图标与文字对齐：`vertical-align` 或 flex `items-center`，并给图标 `flex-shrink: 0`。
- 图标颜色跟随文字层级（`currentColor`），不要五颜六色。

## 组件的完成度

做到"能用"和做到"用起来舒服"之间的差距，几乎全部由用户不会主动注意到的细节构成——单独拎出来每条都不值一提，但缺失时会被整体感知为"这东西有点糙"。

- **好的默认值比可配置项重要**：多数使用者不会改配置，开箱状态就该是对的。一个要传八个 props 才好看的组件，实质上就是不好看。
- **接入成本决定采用率**：一次挂载 + 一个函数调用能解决的，不要求使用者装 provider、接 context、写 hook。
- **边界情况隐形处理**，用户永远不该察觉：标签页切到后台时暂停 toast 计时、堆叠元素之间的缝隙用伪元素填平以免 hover 中断、拖拽期间捕获指针、内容未就位时锁住容器高度防跳动、异步操作期间锁住按钮宽度。
- **文案、命名、动效手感要与组件气质一致**：一个克制的工作台里出现弹跳的确认框，或者严肃组件配俏皮文案，会让人说不出哪里怪但就是觉得拼凑。
