# 动效规则

动效为反馈、定位、连续性服务，不为"看起来酷"服务。做对的动效是隐形的，做错的动效比没有更糟。

## 先决定要不要动

- 动效的四个正当理由：**反馈**（确认操作生效）、**定位**（新元素从哪来）、**连续性**（两个状态间的关系）、**刻意的愉悦**（低频场景的品牌记忆点）。都不占就不加。
- **第一个要问的问题是"用户一天会看到这次动画多少遍"**，愉悦感与频率严格成反比：

| 出现频率 | 决策 |
|---------|------|
| 每天上百次（快捷键、命令面板、聚焦切换） | 不加动画，一次都不加 |
| 每天几十次（hover、列表导航、切 tab） | 砍到几乎隐形，或直接去掉 |
| 偶发（弹窗、抽屉、toast） | 常规动效 |
| 罕见 / 首次（引导、提交反馈、成功庆祝） | 可以有个性、有愉悦感 |

- **键盘触发的操作永远不加动画**（快捷键、方向键导航、tab 聚焦）：它们高频重复，动画只会让操作变卡、和手感脱节。Raycast 的面板开关完全没有动画，这对一天用几百次的东西就是最优解。
- 理由只剩"这样好看"而用户又会频繁看到时，答案是不加。
- 高频短暂 UI（hover 高亮、popover、面板开关）用不对称时序：**进场 0ms 立即出现，出场 100-150ms 淡出**——动作感觉即时，消失不突兀。低频进场可以稍慢、出场要快。

## 只动这些属性

- 位移与形变：只用 `transform` 和 `opacity`（跳过布局和绘制阶段，性能最好）。
- 状态反馈：`color`、`background-color`、`box-shadow`、`opacity` 可以。
- **永远不要动画布局属性**（`width`、`height`、`top`、`left`、`margin`）：每帧触发重排。唯一例外是刻意的容器尺寸过渡（用 `grid-template-rows: 0fr→1fr` 或 FLIP 技巧实现更好）。
- **禁止 `transition: all`**：会动画到预期外的属性，并静默继承未来新增的属性。显式列出要过渡的属性。
- 优先级：CSS transition > WAAPI > CSS keyframes > JS 逐帧。可中断的 UI 用 transition（中断时会重定向到新目标），keyframes 中断会从零重播，只用于预定序列。

## 时长与缓动默认表

| 元素 | 时长 | 缓动 |
|------|------|------|
| 按钮按下反馈 | 100-160ms | `cubic-bezier(0.22, 1, 0.36, 1)` |
| Tooltip、小型 popover | 125-200ms | `ease-out` 或 Enter 曲线 |
| 下拉菜单、select | 150-250ms | `cubic-bezier(0.22, 1, 0.36, 1)` |
| 弹窗、抽屉 | 200-350ms | `cubic-bezier(0.22, 1, 0.36, 1)` |
| 页面内滑动/移位 | 200-300ms | `cubic-bezier(0.25, 1, 0.5, 1)` |
| 页面转场 | 250-400ms | Enter 或 Move 曲线 |
| 简单 hover（颜色/透明度） | 200ms | `ease` |
| 营销页演出性动画 | 最长 1000ms | 弹簧或自定义曲线 |

- 常规 UI 保持 300ms 以内；时长随距离缩放（全屏滑动可超 300ms，6px 的 tooltip 位移要在 150ms 内）。
- 命名曲线（落成 tokens.md 里的 `--ease-*` 变量）：**Enter** `cubic-bezier(0.22, 1, 0.36, 1)`（进场、hover 位移）；**Move** `cubic-bezier(0.25, 1, 0.5, 1)`（滑动、抽屉、面板）；**Drawer（iOS 感）** `cubic-bezier(0.32, 0.72, 0, 1)`。不要凭空自己调曲线，需要别的变体去 easing.dev / easings.co 挑现成的。
- 表里没有的元素按**运动性质**选：进场或出场 → Enter 曲线；在屏幕内移动、形变 → Move 曲线，需要明显的两端加减速时用 `cubic-bezier(0.77, 0, 0.175, 1)`；hover 与颜色变化 → `ease`；匀速运动（跑马灯、进度条）→ `linear`；拿不准 → Enter 曲线。
- 避免 `ease-in` 用于 UI：起步慢，元素滞后于用户操作，感觉迟钝。内置 `ease`/`ease-out` 的加速度偏软，正式场合优先用上面的自定义曲线。
- **慢在用户决策处，快在系统响应处**：长按删除的进度推进 2s linear（慢是为了留出反悔余地），松手归位 200ms ease-out（系统响应必须干脆）。同一个交互的两个方向本来就不该同速。
- **感知性能和真实性能一样值钱**：同样 200ms，`ease-out` 比 `ease-in` 感觉更快，因为用户盯得最紧的头几十毫秒里元素已经动起来了；转得快的 spinner 会让人觉得加载更快（加载时间完全没变）；180ms 的下拉比 400ms 的"跟手"。动效调不动性能，但能改变用户对性能的判断。

## 空间与编排

- popover / 菜单 / tooltip 的 `transform-origin` 设在触发点；弹窗（应用级状态，无锚点）保持 `center`。悬浮层从触发它的元素处长出来，凭空从屏幕中心出现会打断空间感。
- 缩放进场从 `scale(0.85-0.9)` 开始，**永远不要 `scale(0)`**——没有东西是从无中出现的。
- 列表交错进场（stagger）：每项延迟 30-50ms，总时长不超过 300ms；重要元素先动，均匀机械的 stagger 会抹掉层级。
- **成对元素同步**：一起动的元素（弹窗+遮罩、tooltip+箭头）必须共享时长和缓动。"总觉得哪里不对"通常就是配对元素时序不一致。
- **成对状态同步**：开有动画则关也要有；hover 有位移则 focus、pressed 也要有等价反馈。只打磨一半的交互比不打磨更刺眼。
- 方向匹配空间：tab 和轮播的滑动方向要和空间布局一致（向前左出右进，返回相反）。
- 容器和子项二选一：面板滑入时内容应该已经就位，不要容器动完子项再 stagger 一遍。
- 两个内容互换时的粗糙感可以用小幅 `filter: blur(2px)` 过渡掩盖：交叉淡入时眼睛会看到新旧两个独立图层重叠，模糊把它们糊成一个整体，于是被感知为"一次形变"而不是"两个东西换位"。换过缓动和时长都还是别扭时用这招。
- **动效参数要匹配组件气质**（对齐 direction.md 定的个性）：专业后台清脆快速，内容型产品可以略慢、用 `ease` 而不是 `ease-out` 来显得从容（Sonner 的手感就来自这个选择）。同一个产品里的动效风格必须自洽，快慢混搭会让界面显得拼凑。

## 可访问性与设备

- 每个动画都要有 `prefers-reduced-motion: reduce` 路径：关掉位移/缩放动画，保留即时状态切换或纯透明度淡入淡出。
- hover 动画包在 `@media (hover: hover) and (pointer: fine)` 里，否则触屏设备点按时会重播 hover（Tailwind v4 的 `hover:` 已自动处理）。
- 拖拽等直接操纵过程中，元素锁死跟随指针、不加缓动；松手后才允许缓动归位。
- DOM 进场动画用 `@starting-style`；不支持的环境退化为 `data-mounted` 属性切换。

## 性能

- 循环动画离开视口就用 `IntersectionObserver` 暂停，不可见也在烧 GPU。
- `will-change` 只在重动效期间临时开启且只用于 `transform`/`opacity`，动完移除。大量元素永久提升比不提升更糟。
- 不要通过容器上的 CSS 变量驱动拖拽动画（每次更新会重算所有子元素样式），直接在移动元素上设 `transform`。
- CSS 动画跑在合成线程，页面加载繁忙时依然流畅；JS 动画库走主线程，同一时刻会掉帧。预定动画优先 CSS，只有动态、可中断的才交给 JS。

## 反模式

- 挂载即动画、无用户触发：用户什么都没做，界面自己动，只会造成困惑。
- 弹簧参数过弹（晃两下才停）用在工作界面：弹性属于营销页和移动端手势。
- toast、列表项这类高频元素用 keyframes：中断重播从零开始，改用 transition。
- 同组 tooltip 第一个打开后，后续的应立即出现（无进场动画），否则扫过工具栏时感觉卡顿。
- 拖拽边界硬停：越界处加阻尼衰减，硬墙感觉像 bug。
- 骨架屏闪烁：加载低于 200ms 时不显示 loading 态，直接出结果。
- 用动画库的简写 `x`/`y`/`scale` 做关键动效：它们不走硬件加速，页面一忙就掉帧（见 motion-craft.md）。

## 需要动手实现复杂交互时
