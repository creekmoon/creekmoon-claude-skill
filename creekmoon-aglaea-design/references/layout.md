# 布局实现细节

页面形态判断、布局骨架选择和信息分区属于上游结构决策（creekmoon-topaz-pm 的 `references/structure.md`，或用户提供的骨架/线框）——本文件不做这些判断，只负责把已选定的骨架**实现好**：尺寸、栅格、响应式、密度。拿到结构产物后对照落地；没有结构产物时，先按 SKILL.md"边界"一节做最小假设并标注，再回到这里。

## 骨架实现规格

| 骨架 | 实现要点 |
|------|---------|
| 侧边栏 + 内容区 | 侧栏 220-260px，可折叠；内容区才是主角，侧栏视觉上要安静 |
| 顶部导航 + 内容区 | 导航高 48-64px；二级导航用页内 tab |
| 列表-详情分栏 | 列表列 320-400px；选中态要明显；移动端退化为两级页面 |
| 上下分层 | 顶部摘要区收紧（一行关键数字），大面积留给明细表 |
| 居中单列 | 内容宽度 480-720px；登录页不需要左右分屏放插画，除非品牌确有素材 |

## 栅格、宽度与响应式

- 内容区最大宽度：数据密集页可全宽（留 24-32px 边距）；阅读型内容限制 640-720px；营销页区块 1080-1200px 居中。
- 正文行宽不超过 65-75 字符（中文约 35-40 字），超过就分栏或限宽。
- 桌面优先设计的后台也要保证 768px 宽度可用：侧栏折叠、表格横向滚动或降列、操作收进菜单。
- 移动端触控目标 ≥ 44px 高。
- 断点处布局整体切换（三列→单列、侧栏→抽屉），不要让元素以百分比连续挤压变形。

## 密度与留白

- 留白用于分组和节奏，不是越多越高级。数据密集页过度留白会逼操作者滚动而不是扫视。
- 分组优先用间距和 1px 分隔线表达；卡片只在"这个块是独立交互单元"时使用。整页卡片套卡片说明分组逻辑没想清楚。
- 工作面要比导航和 chrome（头部、侧栏、工具条）响亮：用户到达页面后，导航应该在视觉上退后（降低对比度、缩小图标），把注意力让给内容。
- 每条工具栏只做一件事：位置/上下文、视图控制、页面操作分开放，不要混在一根横条里。
