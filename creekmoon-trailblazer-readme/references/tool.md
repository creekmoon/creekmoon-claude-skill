# 工具类项目 README 规范

适用：CLI、MCP Server、SDK、中间件插件、脚手架、可独立安装运行的能力组件。  
读者：使用者优先。目标：**尽快按首选路径跑起来，并清楚能力边界。**

写法对齐「用法优先」类优秀工具 README（例如开箱即用的 MCP：能力一句话 → 关系图 → Docker 快速启动 → 客户端接入 → 工具表 → 环境变量 → 备选源码启动）。架构只点到为止。

返回 [`SKILL.md`](../SKILL.md) 完成读者判定后阅读本文。

## 第一原则（工具）

- **启动与配置是主轴**；架构、模块分层、接手手册不得抢戏
- 首选启动路径必须可复制、可跑；备选路径明确标成「非首选」
- 必须写清 **能做什么 / 不能做什么**（安全边界、只读、权限、不负责的隔离层等）
- 配置表必填项优先，默认值写清；示例里的密钥/连接串用占位符
- 能力面用表呈现（tools / commands / 关键 API）：名称、作用、关键入参
- 不为「像业务 README」而硬写业务主线表、模块职责宽表、接手入口大表
- 详细设计、包结构、对象流转、排障百科不占根 README 主轴

## 内容块与默认顺序

下面的顺序对大多数工具成立（按读者提问顺序排）。但它仍是菜单：**缺证据的块可省，块可并，节名可按项目改写**——只有一条不可让渡：不得把架构或模块清单顶到用法前面。

### 块：标题 + 一句话能力 + 首选启动提示

- 项目名称
- 1 句说清能力（给谁用、解决什么使用问题），用项目自己的词汇，不套句式
- 醒目提示首选启动方式（如「推荐用 Docker」「已发布中央镜像」）
- 如有 fork/上游关系，用一行声明，避免与上游包混淆

### 块：能做什么 / 不能做什么

- 3 条以内「能做什么」
- 明确「不能做什么」与权限/安全边界
- 需要时补一句连接与隔离边界（例如：连的是实例而非库级隔离；限制应在下游账号侧完成）

### 块：极简关系图（可选）

3–5 个节点即可，例如：`Client → 本工具 → 下游系统`。  
表达调用关系与协议，不画内部包结构。全篇只此一张关系图，后文不重复画。

### 块：快速启动（首选路径）

- 给出可复制的 compose / 一键命令 / 安装步骤
- 标出健康检查、监听端口、MCP/服务地址等关键接入点
- 环境变量在示例里给占位符，并指向后文配置表
- 这一块应让「只想用起来」的读者不必往下翻很多

### 块：接到客户端 / 最小调用示例

- 客户端配置 JSON/命令示例（字段名注明以客户端为准）
- 建议的调用/提问顺序（若适用）
- 最小可跑的用法，而不是完整教程书

### 块：能力面清单

| 名称 | 作用 | 关键入参 |
|------|------|----------|

或等价的 commands / HTTP 端点表。  
附带关键规则（如只读 SQL、超时、必填参数约定），用短列表，不写实现原理长文。

### 块：环境变量 / 配置表

| 变量 | 说明 | 默认 |
|------|------|------|

必填优先；与行为相关的策略（超时降级、连接池等）用一两句说明即可。

### 块：备选启动（非首选）

源码本地、本地构建镜像等。开头标明「需要改代码或不走中央发布时再走这条路」，避免与首选路径并列抢戏。命令不重复贴——与首选路径相同的步骤回指前块。

### 块：架构点到为止（可选）

满足以下之一再写，且 **≤1 小节或 3–5 行**：

- 用户明确要二次开发
- 顶层入口不写会让维护者完全迷路

只点：入口文件、顶层目录、扩展点名称。  
不写接手手册、业务主线表、宽表（那是接手场景的东西）。

可选：极短自测命令、许可证——放在文末即可。

## 更新已有 README（工具）

- 保留仍然正确的安装命令、配置项、工具表；**可操作内容只能保留或迁移，不得删除**
- 把「架构/模块长文」后移或删到只剩点到为止
- 若同时存在多种启动方式，重排为「一个首选 + 其余备选」
- 补齐缺失的「不能做什么」与最小客户端示例
- 不为统一风格全文重写；只动需要动的部分

## 表达规则

- 命令与 JSON 必须可复制，且与仓库当前一致（过时命令比没有更糟）
- 段落短；先让读者跑起来，再谈实现
- 每个论断带具体锚点（真实工具名、参数名、端口、默认值）
- 表格各司其职，默认 ≤2 张宽表；列填不出真内容就删列
- 同一信息（启动命令、接入地址、配置项）全篇只出现一次；后文回指，不重复贴
- 不用「面向 X 的一站式闭环平台」套话；不堆事实表；不写研究过程

## 常见反模式（工具）

- 写成业务 PRD / 接手框架，读者找不到怎么启动
- 把模块清单或包结构放在最前
- 漏掉「不能做什么」或安全边界
- 首选路径与备选路径并列、分不清推荐哪条；同一命令重复贴
- 配置项散落在长文里，没有表
- 只有架构没有可复制命令；或命令过时与仓库不一致
- 把内部实现细节、类图、完整排障手册塞进根 README
- 开头两句像句式填空；凑结构的一行事实表
