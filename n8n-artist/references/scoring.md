# 场景 F：工作流评分（判定细则）

执行级总清单（含扣分表）在 [SKILL.md](../SKILL.md) 的「检查/评分总清单」——检查、体检、评分任务先过那张表，逐项留痕。本文件是判定细则：拿不准时怎么判、报告怎么出。

## 数据前提

- 命名 / 参数 / 业务编排三维：靠 workflow JSON 静态检查（MCP 或粘贴均可）
- 历史运行维度：靠执行历史（MCP 路径）。粘贴 JSON 路径下本维度记 N/A，总分按 30 分制给出并注明

## 字段级失效的判定方法（"上游结构没这个属性却引用了"）

| 上游节点类型 | 判定方式 | 置信度 |
|-------------|---------|--------|
| Code 节点 | 读代码确认返回结构 | 确定 |
| Set / Edit Fields | 看字段定义 | 确定 |
| 有 pinData | 直接对键名 | 确定 |
| 有执行采样数据 | 对采样输出的键名 | 确定 |
| HTTP Request 等外部节点，无采样 | 无法静态确认 | 待验证（列出不扣分） |

证据矛盾时（如代码里有但采样数据里没有）取低置信度，按"疑似"计。

## 历史运行维度的样本要求

- 样本量：最近 50-100 次执行；不足 50 次全取，并在报告中注明样本量
- 成功率按 status 统计；错误签名按报错原文归类（参照 [agent-tool-orchestration.md](agent-tool-orchestration.md) E7 的错误签名对照表）
- 耗时突增：近期执行耗时达到历史均值 3 倍以上
- draft ≠ active：已激活工作流的草稿里有未发布修复，说明线上仍在跑旧问题

## 定级

36-40 🟢 优秀 / 30-35 🟢 良好 / 24-29 🟡 合格 / 18-23 🟠 较差 / <18 🔴 急需整治

各维度扣到 0 分为止；同一问题不跨维度重复扣分（按最直接相关的维度扣一次）。

## 提示项（不扣分）

以下只作建议列入报告提示区，**不纳入评分、不作硬性规定**：外部节点的 error output / retry / error workflow 配置、执行数据保留策略、凭据环境隔离等。报告格式见 [report-spec.md](report-spec.md)。
