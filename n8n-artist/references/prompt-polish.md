# 场景 D：LLM 节点 Prompt 瘦身

LLM 节点的提示词按 token 计费，且每句话都在稀释模型的注意力。废话不是风格问题，是成本问题和指令命中率问题。

**适用节点**：`@n8n/n8n-nodes-langchain.*` 下的 AI Agent、Basic LLM Chain、OpenAI、Anthropic 等节点的 `text` / `systemMessage` / `prompt` 字段。

## D0. 改动分级与确认门（先读这个）

改提示词是高危操作——一处措辞变化就可能改变模型的触发判断、输出结构或工具调用行为，而且**不会报错，只会静默表现变差**。因此：

**改动分级：**

- **保守档（默认）**：只删零信息内容（空话开场白、字面完全重复的约束）、修标点格式。不改结构、不改语序、不改规则表述方式。信号词/触发条件列举只能增补，不能删减。
- **重构档**：仅当用户明确提出"重构 / 重写 / 大改 / 激进改动"时启用。允许调整结构（如三段式）、改写规则表述、重排顺序，但仍受确认门约束，且每条改动都要说明理由。

**确认门（强制，两档通用）：**

1. 任何 prompt 改动，先输出「前后对比预览」：原文全文、优化后全文、逐条改动理由
2. 用户明确同意前，不得应用到工作流——包括只改一个标点
3. 用户说"直接改"时，先给完整预览再改，可不等二次确认，但预览一条都不能省

**保守档红线：**

- **信号词/触发条件列举：只增不删**。删掉一个信号词，一类问题就静默不再触发（真实事故：触发词表改写时漏掉一个时间类信号词，该类追问从此不再触发检索，且无任何报错）
- **规则条数与顺序：不压缩、不重排**。压缩表述会丢约束；模型对编号规则的遵循度高于散文
- **不新增原文没有的结构性标记**（如【任务】【约束】这类标签）——风格变化本身就是行为变化
- 输出格式约束、`{{ }}` 表达式位置：原样保留
- **一次只改一个维度**：prompt 改动不要与换模型、调参数同时进行，否则表现变化无法归因

## D1. 删什么（废话识别清单）

1. **零信息开场白**："你是一个有帮助的助手"、"请你"、"我希望你能"、"作为一个AI"——模型默认行为，写了等于没写。
2. **同一约束重复表述**："输出必须简洁"出现三次 → 保留一次。重复不会提高遵守率，只会稀释其他指令。
3. **冗长角色铺垫**：300 字人设压成一句角色定义（"你是跨境电商客服，负责订单查询与退换政策答复"），情绪化的形容词堆砌全删。
4. **散乱规则的流水账**：十条零散叮嘱合并为结构化三段——**任务 / 约束 / 输出格式**。输出格式放最后并加明确标题（如「【输出要求】」）。
5. **模型已知的常识叮嘱**："不要编造事实"、"回答要专业"——除非配合具体机制（如"不知道时回复'转人工'，禁止猜测"），否则是空话。

## D2. 不能删什么（保留清单）

- **业务上下文与术语**：SKU、状态码、内部系统名——模型不知道你们的业务
- **few-shot 示例**：示例是 prompt 里 token 花得最值的地方，一个对比例顶十条规则
- **边界条件与异常要求**："查不到订单时如何回复"、"用户情绪激动时转人工"
- **输出 schema / 格式约束**：下游节点要解析输出时，这是硬契约
- **`{{ }}` 表达式**：优化 prompt 时**绝对不能动**变量占位符（`{{ $json.orderId }}`），改坏了就是场景 C 的失效引用

## D3. 工作方式

1. 先量原文：中文字数 ≈ token 数，英文按 chars/4 粗估
2. 给优化版，并输出对比表：**每条删除/改动内容 + 理由**（为什么改了不损失指令覆盖率）
3. 拿不准的句子不删，标注「存疑保留」——宁可少删，不可误删业务约束
4. 语言保持原文（中文 prompt 不因"模型更懂英文"擅自翻译，除非用户要求）
5. **确认门**：对比预览经用户明确同意后，才允许应用到工作流（见 D0）；用户要求直接改时，先给完整预览再执行

## D4. 输出模板（即确认门要求的「前后对比预览」）

```markdown
## Prompt 瘦身：AI Agent「客服回复」

**原文 412 字 → 优化后 168 字（-59%）**

### 删除项
| 原文 | 理由 |
|------|------|
| "你是一个有帮助的助手，请你认真回答" | 零信息开场白，模型默认即如此 |
| "回答要简洁"（第 2、3 次出现） | 重复约束，保留第 1 次 |
| "你需要非常专业地处理每一个问题" | 无操作含义的形容词堆砌 |

### 优化后 Prompt
你是跨境电商客服，负责订单查询与退换政策答复。
【任务】根据用户问题查询订单状态并答复。
【约束】
- 仅答复订单/退换相关问题，其他话题引导至人工
- 查不到订单时回复"未查询到相关订单"，禁止编造单号
【输出要求】
- 100 字内，先结论后细节
- 涉及单号时用 {{ $json.orderId }}

### 保留说明
- 保留"禁止编造单号"：有明确触发场景和替代行为，不是空话
- 保留输出格式段：下游「解析回复」节点按此结构取数
```
